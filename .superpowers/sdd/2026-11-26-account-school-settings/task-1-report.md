## Implementation summary

- Added `school_allowed_domains`, `user_settings`, `foundit_notifications`, `user_account_requests`, and `school_review_settings`, with RLS enabled and explicit role grants. Seeded `phichai.ac.th` and default review settings for the Phichai school.
- Replaced `public.is_phichai_email()` to derive eligibility from the allow-list. Updated the auth profile-provisioning trigger to use the same allow-list and provision settings; profile display-name metadata is read only as a display-name source and is not used for authorization.
- Added a private `is_school_admin(uuid)` security-definer check constrained to the Phichai school anchor and backed by `profiles.role`; it checks the authenticated user's database profile and allow-listed JWT email. Trigger helpers are private, use `search_path = ''`, schema-qualify relations, and have public/anon/authenticated direct execution revoked. Authenticated has only the schema/function access needed to invoke the boolean admin predicate from RLS.
- Added member-owned settings/notification/account-request policies, admin policies for profiles, domains, locations, review settings, and account requests, plus column-limited updates for display name, notification read state, and admin status/settings changes.
- Added locked-parent-row last-domain and last-admin guards. Domain removal leaves profiles and school data untouched; no session revocation claim or service-role client surface was added.
- Made the initial report status and restrictive insert policy consult the same review settings. The trigger affects newly inserted reports only.
- Added private status/new-lead notification triggers for report creators, claimants, and report owners; notifications contain identifiers and event category only, not private claim/lead text, and respect category preferences.
